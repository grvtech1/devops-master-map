🚨 Production War-Room — 5 Real Incidents & Post-Mortems

Must Know for 3+ YOE

Real companies me hone wale 5 sabse common outages: symptom kya dikha, investigation kahan hui, root cause kya nikla, aur permanent fix kya tha.

SEV-1 OUTAGE 1. The 502 Bad Gateway Rolling Update Storm Downtime: 18 min

Naya application version deploy karte hi users ko 15-20 second tak HTTP 502 Bad Gateway errors aane lage, jabki purane pods healthy the.

🔍 Symptom & Investigation ALB access logs me 502 spike. kubectl rollout status ne bola deployment successful, par ALB target group me naye pods unready the aur purane pods abruptly terminate ho gaye.
💥 Asli Root Cause 1) readinessProbe missing tha — Kube-proxy ne pod ko start hote hi (0 sec me) endpoint bana diya jabki app 6 sec leti thi start hone me.
2) preStop hook nahi tha — Purane pod ko SIGTERM milte hi socket band ho gaya, par ALB ke paas in-flight requests atki reh gayi.
🛠️ Permanent Fix (YAML) lifecycle: preStop: exec: { command: ["sh", "-c", "sleep 10"] } readinessProbe: httpGet: { path: /healthz, port: 8080 } initialDelaySeconds: 5
🎯 Interview Defense Line "Zero-downtime rolling updates require both a tuned readinessProbe so traffic isn't routed before warm-up, and a preStop sleep hook to drain in-flight connections before SIGKILL."
SEV-2 CRASH 2. OOMKilled 137 JVM Heap Memory Explosion Intermittent CrashLoop

Java Spring-Boot application pod har 25 minute me crash ho jata tha. kubectl get pods me Exit Code 137 dikhta tha.

🔍 Symptom & Investigation dmesg -T | grep -i oom me aaya: "Memory cgroup out of memory: Killed process java". Java logs me koi OutOfMemoryError exception nahi tha!
💥 Asli Root Cause Java developer ne -Xmx1024m set kiya tha aur K8s container limit 1024Mi thi. JVM sirf Heap nahi, Metaspace + Thread stacks + GC overhead (~300MB extra) bhi leta hai. Total 1350MB hua toh Linux kernel ne bahar se SIGKILL maar diya!
🛠️ Permanent Fix Hardcoded -Xmx hatakar container-aware flag lagaya:
-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0
Container memory limit ko 1.5Gi kiya taaki non-heap memory ke liye headroom bache.
🎯 Interview Defense Line "Exit code 137 without JVM stack traces indicates Linux kernel cgroup OOMKill. Always set MaxRAMPercentage to 70-75% leaving headroom for thread stacks and native buffers."
SEV-1 LATENCY 3. CoreDNS ndots:5 External API 5-Second Latency Spike High Scale Outage

Peak diwali sale ke waqt Payment Gateway (Stripe / Razorpay) ke calls achanak 5 second me timeout hone lage.

🔍 Symptom & Investigation Pod CPU & RAM normal the. Lekin CoreDNS ke pods par CPU 100% pahunch gaya tha aur packet drop ho rahe the. tcpdump port 53 me lakho unwanted lookups dikhe.
💥 Asli Root Cause K8s default /etc/resolv.conf me ndots:5 hota hai. api.razorpay.com me 2 dots the (<5). Isliye K8s ne pehle 4 internal search domains query kiye: api.razorpay.com.default.svc.cluster.local ➔ CoreDNS exhausted!
🛠️ Permanent Fix Pod spec me FQDN use kiya (trailing dot: api.razorpay.com.) ya pod dnsConfig me ndots ko 2 kiya: dnsConfig: options: - name: ndots value: "2"
🎯 Interview Defense Line "Kubernetes ndots:5 default causes severe DNS amplification for external domains. We mitigate this using NodeLocal DNSCache, appending trailing dots, or tuning ndots:2 in high-throughput workloads."
BILL SHOCK 4. Silent $3,500 AWS Bill Explosion (NAT Gateway & Orphan EBS) Financial Bleeding

Traffic growth sirf 10% hua, par AWS monthly billing statement me $3,500 extra charges aaye.

🔍 Symptom & Investigation AWS Cost Explorer me do line items explode hue: 1) EC2-Other: NatGateway-Bytes aur 2) EBS:VolumeUsage.gp2.
💥 Asli Root Cause 1) Private worker nodes ECR / S3 se gigabytes of docker images pull kar rahe the via NAT Gateway ($0.045/GB) bina VPC Gateway Endpoint ke.
2) StatefulSet pods delete hue par unke EBS volumes (PV) "Available" state me unattached baithe the aur AWS unka bill roz charge kar raha tha!
🛠️ Permanent Fix 1) Free S3 Gateway Endpoint add kiya (NAT data transfer $0 ho gaya).
2) Automated AWS Lambda / bash cleanup script lagaya unattached EBS volumes terminate karne ke liye.
🎯 Interview Defense Line "NAT Gateway data processing is a classic hidden AWS cost trap. Enabling free S3 and ECR VPC Endpoints eliminated cross-NAT image pull costs, and automated EBS orphan cleanup saves thousands monthly."
DAY-2 OPS 5. Zero-Downtime EKS Upgrade Playbook (1.28 ➔ 1.30) Production Hardening

Production Kubernetes cluster ko bina customer outage aur bina 1 second ke downtime ke safely upgrade karne ka standard enterprise SOP.

📋 Pre-Flight Checks 1) kubent ya pluto chalao deprecated APIs detect karne ke liye.
2) Har critical deployment me PodDisruptionBudget (PDB) verify karo (minAvailable ≥ 1).
🔄 Sequence of Upgrade Hamesha isi order me upgrade hota hai:
Add-ons pehle (VPC-CNI ➔ CoreDNS ➔ kube-proxy) ➔ EKS Control Plane ➔ Worker Node Groups. Kabhi ulta nahi!
🛠️ Node Rolling Replacement Naya node group launch karo with new AMI. Purane nodes ko gracefully drain karo:
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
Traffic naye nodes par shift hoga, phir purana node group terminate karo.
🎯 Interview Defense Line "In enterprise EKS upgrades, we audit deprecated APIs with Pluto, upgrade core add-ons first, apply control plane version bumps via Terraform, and then roll worker nodes using PDBs and graceful cordons."

🔄 Foundation vs Frontier — Modern Architecture Comparison

90% Prod vs Modern Next-Gen

Aksar log sochte hain "old vs new", jabki ye "Foundation (90% Production) vs Frontier (Next-Gen Optimization)" hai. Modern tool tabhi samajh aayega jab purani bottleneck pata ho.

1. Cluster Routing Networking
Foundation kube-proxy + iptables: Linear O(N) chain evaluation. 5,000 services par packet delay & CPU spike.
Frontier Cilium eBPF: Kernel BPF hash-table lookup O(1). Direct socket routing, bypasses slow iptables completely.
2. Pod IP Networking VPC Latency
Foundation Calico Overlay: VXLAN packet-in-packet. Pod IP VPC me unroutable. ALB has to double-hop via NodePort.
Frontier AWS VPC CNI (IP Mode): Real secondary VPC IPs for each Pod. ALB routes directly to Pod IP without extra hop.
3. Pod AWS Authentication Security (IAM)
Foundation IRSA (OIDC Provider): Cluster OIDC setup required in IAM. Massive JSON trust policies with 2048-char limits.
Frontier EKS Pod Identity (Nov 2023): Zero OIDC providers needed. Native EKS agent daemonset directly binds IAM roles.
4. Ingress & Traffic Splitting Routing API
Foundation Ingress-Nginx: Basic spec. Canary routing, rate limits require messy vendor-specific annotations.
Frontier Gateway API: Role-oriented (GatewayClass, Gateway, HTTPRoute). Native 90/10 canary traffic splitting without annotations.
5. Node Autoscaling Compute Scaling
Foundation Cluster Autoscaler: Tied to EC2 Auto Scaling Groups (ASG). 3 to 5 minutes launch delay. Rigid instance types.
Frontier Karpenter: Group-less! Direct EC2 Fleet API. Spins up optimal right-sized instances in 40s + auto-consolidation.
6. Control Plane Operations Control Plane
Foundation kubeadm / Self-Managed: Manual TLS certs, etcd raft quorum, static pods. Teaches underlying mechanical plumbing.
Frontier EKS Managed Control Plane: AWS manages HA master nodes across 3 AZs. Black box API endpoint ($0.10/hr).
